# Service Symfony 

Un service dans Symfony est une classe PHP qui effectue une tâche spécifique et peut être réutilisée à travers l'application. Les services sont généralement utilisés pour encapsuler la logique métier, les interactions avec les bases de données, les appels à des API externes, ou toute autre fonctionnalité qui ne relève pas directement de la présentation (comme les contrôleurs).

Il est très important d'encapsuler la logique métier dans des services pour plusieurs raisons :
- **Réutilisabilité** : Les services peuvent être utilisés dans plusieurs parties de l'application sans dupliquer le code.
- **Testabilité** : Les services sont plus faciles à tester de manière isolée, ce qui améliore la qualité du code.
- **Séparation des préoccupations** : En séparant la logique métier des contrôleurs, on rend le code plus propre et plus maintenable.

> L'utilisation de services permet de suivre les principes SOLID, notamment le principe de responsabilité unique (Single Responsibility Principle), car chaque service doit faire une seule chose et le faire bien (Single responsibilty)




### Why doesn't it exist?

Because of Symfony’s **Autowiring**. Creating a service in modern Symfony is intentionally trivial. Since you don't need to manually register every class in a configuration file anymore, a code generator isn't strictly necessary. Any plain PHP class you create inside the `src/` directory is automatically recognized as a service by Symfony.

---

### Comment créer un service dans Symfony ?

Pour écrire un service dans Symfony, il suffit de créer une classe PHP classique dans le dossier `src`. Symfony s'occupe du reste en coulisses.


1. Créer un fichier php dans `src/` ( `src/Service/WelcomeService.php`).
2. Définissez son namespace et sa classe, et ajoutez la logique métier que vous souhaitez encapsuler.

> Le namespace est obligatoire pour pouvoir importer la classe plus tard, il doit respecter la structure de dossier de votre projet. 
> Par exemple, si votre classe se trouve dans `src/Service/WelcomeService.php`, son namespace doit être `App\Service`.
> À noter que `App` est le namespace de base pour tout ce qui se trouve dans le dossier `src/` de votre projet Symfony, il faut donc bien écrire App et pas src dans le namespace.

```php
<?php

namespace App\Service;

class WelcomeService
{
    public function salute(string $name): string
    {
        return "Welcome, $name!";
    }

    public function bye(string $name): string
    {
        return 'Good bye, ' . $name . '! See you soon !';
    }

    public function checkFeelings(string $name) : string
    {
        return "How are you feeling today  $name ?";
    }
    public function checkWeather(string $name) : string
    {
        return "How is the weather today  $name ?";
    }
}

```

3. Injectez le service dans un contrôleur ou un autre service pour l'utiliser.

```php
<?php

namespace App\Controller;

use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Annotation\Route;
use App\Service\WelcomeService;



class HomeController extends AbstractController
{
    #[Route('/home', name: 'app_home')]
    public function index(WelcomeService $myService): Response
    {
        $message = $myService->salute();
        
        return new Response($message);
    }
}
```

> *symfony console make:service ?* : Non, Il n'existe pas de commande pour générer un service dans Symfony, car il n'y a rien à configurer pour que Symfony reconnaisse une classe comme un service. Tant que vous vous trompez pas sur le namespace et que votre classe se trouve dans le dossier `src/`, Symfony l'enregistrera automatiquement comme un service.


### Quand créer un service ?

Pour faire simple : si vous écrivez du code dans un contrôleur ou un composant qui n'est pas directement lié à la présentation (affichage) ou à la gestion des requêtes HTTP, alors ce code devrait probablement être déplacé dans un service.

Cela inclut donc :
- La logique métier (calculs, règles de validation, etc.)
- Les interactions avec les bases de données (via des repositories)
- Les appels à des API externes
- Toute autre fonctionnalité qui peut être réutilisée dans plusieurs parties de l'application

### Conclusion 
- Idéalement un contrôleur ne devrait pas utiliser directement un Repository ou l'EntityManagerInterface pour interagir avec la base de données, mais plutôt injecter un service qui encapsule cette logique d'accès aux données. De même, un composant ne devrait pas contenir de logique métier complexe, mais plutôt déléguer cette logique à un service. On appelle cela : **Pousser la logique vers le haut.**

- Un service est une simple classe PHP créée dans le dossier src et dont on a défini un namespace correct.

- Un service est accessible en l'injectant dans un contrôleur de la même façon que l'EntityManagerInterface, MailerInterface, etc. (autowiring)

- Créer des services est essentiel pour correctement tester votre code, car celà permet d'isoler les fonctionnalitées du *controller* (requête HTTP) et de la view pour tester **VOTRE** partie du code (la logique métier) de manière fiable et rapide.

Souvenez-vous donc : quand vous installez une extension avec composer, vous injectez sa classe dans votre contrôleur pour l'utiliser (Gotenberg pour les PDF par exemple), on peut considérer cette classe comme un service. Dans ce cours vous avez simplement appris à créer vos propres services pour encapsuler votre logique métier, mais vous pouvez aussi utiliser des services tiers (comme Gotenberg) pour faire des choses plus complexes sans avoir à réinventer la roue.
