## Documents de pré-production - Objectif cahier des charges
- Synopsis : Une **brève** description de : l'application, de son but et de ses fonctionnalités clés.
- User Stories : Une liste des fonctionnalités de l'application du point de vue de l'utilisateur final, décrivant ce que l'utilisateur peut faire avec l'application. "As a [type of user], I want [an action] so that [a benefit/a value]".
- Diagrammes de cas d'utilisation
- MCD / MLD (diagrammes de bases de données)
- Cahier des charges

## Documents de pré-production - Objectif Maquettes
- Maquettes wireframe 
- Maquettes haute-fidélité orientée components
- Maquettes interactive (prototype Figma)
- Arborescence des composants front-end

> Maquettes wireframe : Une maquette en noir et blanc qui montre la structure de chaque page de l'application, sans se soucier de l'apparence visuelle. Elle inclut les emplacements des éléments principaux tels que les boutons, les champs de formulaire, les images et les zones de texte. Concrètement c'est le squelette de l'application que tout le monde dessine sur une feuille avant de commencer le design mais en numérique.

> Maquettes haute-fidélité : C'est la suite du wireframe qui définit l'apparence définitive de l'application (même si l'UI peut changer les développeurs doivent avoir une référence claire). Elle inclut la palette de couleurs, les polices, les espacements entre les blocs.

> Maquette orientée components : Une maquette dans laquelle vous avez utilisé les fonctionnalités de composants réutilisables de Figma pour créer des éléments d'interface utilisateur cohérents et modulaires (boutons, formulaires, cartes, etc, popup, toasts). Chaque composant peut être dupliqué plusieurs fois dans la maquette, ce qui facilite la gestion des modifications et assure une uniformité visuelle car *quand le composant change tous ses clones changent aussi*.
