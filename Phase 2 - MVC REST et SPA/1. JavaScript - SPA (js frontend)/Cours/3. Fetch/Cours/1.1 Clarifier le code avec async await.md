# Ecrire du code asyncrone plus propre.

Vous l'avez surement remarqué la syntaxe des fonctions `then` de l'API `fetch` peut être difficile à lire.

Les fonctions fléchées passées en paramètre sont obligatoire car, au même titre que `setTimeout` ou `setInterval`, `fetch` effectue une opération asyncrone : une requete HTTP.
```js

setTimeout(function(){
    // ... s'execute au bout de deux secondes.
},2000);


fetch("http://...").then(function(reponseHTTP){
    // ... s'execute à la réception de la réponse HTTP
})


```
Une opération asyncrone d'execute après le reste du code et néccesite donc de fournir aux fonctions `then()` des fonctions de rappels : des fonctions qui doivent s'executer plus tard (à la reception de la réponse du serveur).

```js
fetch("https://pokebuildapi.fr/api/v1/pokemon/limit/10")
.then(response_obj => response_obj.json())
.then(pokemons_arr => {
    pokemons_arr.forEach(pokemon_obj => {
        console.log(pokemon_obj.name);
    });
});
```

> **Note :** Même la fonction `response.json()` est asyncrone, car le traitement de données JSON peut prendre beaucoup de temps dans le cas d'un tableau de milliers d'éléments.

Il est néanmoins possible de rendre une opération asyncrone bloquante et donc de supprimer toutes ces fonctions illisibles.

Grâce à la syntaxe async await.

```js
// Schéma de async await
const data = await operationAsyncrone(); 
```

`await` permet de rendre bloquant une promesse.

## Clarifier le code avec async await

1. Pour ce faire il faut d'abord définir une fonction comme asyncrone :
```js
async function main(){

}
```

2. Je peux ensuite appeler `fetch` dedans et utiliser le mot clé `await` pour attendre le retour de la réponse et récupérer le résultat (une objet) de façon plus traditionnel : avec une affection.

```js
async function main(){
    const response_obj = await fetch("https://pokebuildapi.fr/api/v1/pokemon/limit/10");

    const pokemons_arr = await response_obj.json();
    
    console.log(pokemons_arr);
}
main();
```

On retrouve une lecture syncrone du code (ligne par ligne), c'est bien plus court que la syntaxe des `then` :

```js
fetch("https://pokebuildapi.fr/api/v1/pokemon/limit/10")
.then(response_obj => response_obj.json())
.then(pokemons_arr => {
    pokemons_arr.forEach(pokemon_obj => {
        console.log(pokemon_obj.name);
    });
});
```

> Il est bon a savoir que le code n'est pas devenu magiquement syncrone, l'asyncronité a juste été déplacé sur la fonction main.
> Je peux donc toujours utiliser then pour effectuer une opération après l'execution de tout les await.
>```js
>async function main(){
>    const response_obj = await fetch("https://pokebuildapi.fr/api/v1/pokemon/limit/10");
>    const pokemons_arr = await response_obj.json();
>    console.log(pokemons_arr);
>}
>main().then(()=>{console.log("Fetch terminé")});
>```

## Gestion d'erreur

Utilisez try..catch pour gérer les erreurs.

```js
async function main(){
    try{
        // HTTP REQUEST  : fetch ->
        // HTTP RESPONSE : response <- 
        const response_obj = await fetch("https://pokebuildapi.fr/api/v1/pokemon/limit/10");

        const pokemons_arr = await response_obj.json();
    
        console.log(pokemons_arr);

    }catch(error_obj){
        console.warn(error_obj);
    }
}
main();
```
