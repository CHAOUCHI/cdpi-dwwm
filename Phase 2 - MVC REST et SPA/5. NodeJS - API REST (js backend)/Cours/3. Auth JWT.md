# Autorization JWT


## POST /register
La route /register crée un nouvelle utilisateur dans la table User.

1. Vérifier les identifiants email et password sont présents dans le body de la requête.
2. Effectuer un INSERT INTO avec la méthode UserModel.create() de Sequelize.

```js
app.post('/register', async (req, res) => {
    const { email, password, verifiedPassword } = req.body;

    if (!email || !password || !verifiedPassword) {
        return res.status(400).json({ message: 'Email, password and verifiedPassword are required' });
    }

    if (password !== verifiedPassword) {
        return res.status(400).json({ message: 'Passwords do not match' });
    }

    try {
        const newUser = await UserModel.create({ email, password });
        res.status(201).json({ message: 'User registered successfully', userId: newUser.id });
    } catch (error) {
        res.status(500).json({ message: 'Error registering user', error: error.message });
    }
});
```

## POST /login 
La route /login vérifie les identifiants de connexion et fournit un token jwt dans le cookies pour Authenfier l'utilisateur.

Ce token contient le user_id de la même façon que $_SESSION en PHP contient le user_id de l'utilisateur authentifié.

1. Vérifier les identifiants email et password sont présents dans le body de la requête.
2. Effectuer un SELECT avec la méthode UserModel.findOne() de Sequelize pour vérifier que les identifiants sont corrects.
3. Si les identifiants sont corrects, créer un token JWT avec la méthode jwt.sign() en y plaçant le user_id de l'utilisateur.
4. Placer le token JWT dans un cookie HTTPOnly avec la méthode res.cookie() d'Express.

```js
app.post('/login', async (req, res) => {
    const { email, password } = req.body;
    if (!email || !password) {
        return res.status(400).json({ message: 'Email and password are required' });
    }
    try {
        const user = await UserModel.findOne({ where: { email, password } });
        if (!user) {
            return res.status(401).json({ message: 'Invalid email or password' });
        }

        const token = jwt.sign({ userId: user.id }, JWT_SECRET, { expiresIn: '1h' });
        res.cookie('token', token, { httpOnly: true });
        res.json({ message: 'Login successful' });
    } catch (error) {
        res.status(500).json({ message: 'Error logging in', error: error.message });
    }
});
```

> **Note:** Dans une application réelle, il est important de hasher les mots de passe avant de les stocker dans la base de données. Utilisez des bibliothèques comme bcrypt pour cela.

> **Note Role :** Pour simplifier l'exemple, nous n'avons pas implémenté de gestion des rôles (admin, user, etc.). Dans une application réelle, vous devriez inclure le rôle en tant qu'attribut dans le token JWT et vérifier les autorisations dans les routes protégées.


## Middleware isLoggedInJWT
Le middleware isLoggedInJWT vérifie la présence et la validité du token JWT dans les cookies de la requête.

```js
function isLoggedInJWT(UserModel) {
    return (req,res,next)=>{
        const token = req.cookies.token;
        if (!token) {
            return res.status(401).json({ message: 'Unauthorized: No token provided' });
        }
        try {
            const decoded = jwt.verify(token, JWT_SECRET);
            req.userId = decoded.userId;
            req.user = await UserModel.findByPk(req.userId); // Récupérer l'utilisateur connecté
            next();
        } catch (error) {
            return res.status(401).json({ message: 'Unauthorized: Invalid token' });
        }
    }
}
```

### Verrouiller les routes privés de notre application

Un middleware est une fonctio qui s'execute à l'appelle d'une route mais avant que la route demandez par l'utilisateur ne soit défini par le router.

Concrètement je peux faire en sorte d'executer la fonction isLooggedInJWT avant les routes qui neccessite ld'être connecté.

Les routes de mon serveur s'execute dans cette ordre :

```js

// Route public
app.post("/register",(req,res)=>{});
app.post("/login",(req,res)=>{});


// Route privé
app.get("/tasks",(req,res)=>{});
app.get("/task/:id",(req,res)=>{});
app.post("/task",(req,res)=>{});
app.post("/register",(req,res)=>{});

```

Un middleware peut être appellée avec la fonction app.use().

Il faut donc appeller app.use() avant les routes privés
```js

// Route public
app.post("/register",(req,res)=>{});
app.post("/login",(req,res)=>{});


app.use(isLoggedInJWT(User)); 

// Route privé
app.get("/tasks",(req,res)=>{});
app.get("/task/:id",(req,res)=>{});
app.post("/task",(req,res)=>{});
app.post("/register",(req,res)=>{});
```
