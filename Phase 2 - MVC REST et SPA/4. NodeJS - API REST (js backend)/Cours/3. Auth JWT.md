# Autorisation JWT

Un token JWT est un jeton d'authentification sécurisé qui permet de vérifier l'identité d'un utilisateur sans avoir à stocker des informations de session côté serveur.

Il est souvent utilisé dans les applications web modernes pour gérer l'authentification et l'autorisation des utilisateurs.

Un token JWT est composé de trois parties séparées par des points : l'en-tête (header), la charge utile (payload) et la signature.

- L'en-tête contient des informations sur le type de token et l'algorithme de signature utilisé (géré automatiquement par la bibliothèque jsonwebtoken).
- La charge utile contient les informations sur l'utilisateur (par exemple, son identifiant, son rôle, etc.).
- La signature est utilisée pour vérifier l'intégrité du token et s'assurer qu'il n'a pas été altéré.

## Comment le token est-il sécurisé ?

Le token JWT est sécurisé grâce à la signature numérique. Lorsqu'un token est créé, il est signé avec une clé secrète connue uniquement du serveur.

La signature est la concaténation du header encodé en base64, du payload encodé en base64 et d'une clé secrète, le tout haché avec un algorithme de hachage (par exemple HMAC SHA256).

Ainsi, même si le payload est modifié (par exemple en changeant le user_id ou le role contenu dans le payload), la signature ne correspondra plus et le token sera invalide.

*Schéma d'un token JWT*
```json
{
    "header": {
        "alg": "HS256",
        "typ": "JWT"
    },
    "payload": {
        "user_id": 123,
        "role": "admin",
        "exp": 1712345678
    },
    "signature": Chiffrement(
        base64Encodage(header) + "." +
        base64Encodage(payload),
        secret)
}
```

## POST /register
La route /register crée un nouvel utilisateur dans la table User.

1. Vérifier que les champs email, password et verifiedPassword sont présents dans le body de la requête.
2. Effectuer un INSERT INTO avec la méthode UserModel.create() de Sequelize.

```js
app.post('/register', async (req, res) => {
    const { email, password, verifiedPassword } = req.body;

    if (!email || !password || !verifiedPassword) {
        return res.status(400).json({ message: 'Email, password and verifiedPassword are required' });
    }

    if (password !== verifiedPassword) {
        return res.status(400).json({ message: 'Passwords do not match' });
    }

    try {
        const newUser = await UserModel.create({ email, password });
        res.status(201).json({ message: 'User registered successfully', userId: newUser.id });
    } catch (error) {
        res.status(500).json({ message: 'Error registering user', error: error.message });
    }
});
```

## POST /login 
La route /login vérifie les identifiants de connexion et fournit un token JWT dans un cookie pour authentifier l'utilisateur.

Ce token contient le user_id de la même façon que $_SESSION en PHP contient le user_id de l'utilisateur authentifié.

1. Vérifier que les champs email et password sont présents dans le body de la requête.
2. Effectuer un SELECT avec la méthode UserModel.findOne() de Sequelize pour vérifier que les identifiants sont corrects.
3. Si les identifiants sont corrects, créer un token JWT avec la méthode jwt.sign() en y plaçant le user_id de l'utilisateur.
4. Placer le token JWT dans un cookie HTTPOnly avec la méthode res.cookie() d'Express.

```js
const JWT_SECRET = 'votre_cle_secrete_pour_jwt'; // Utilisez une clé secrète sécurisée dans une application réelle
app.post('/login', async (req, res) => {
    const { email, password } = req.body;
    if (!email || !password) {
        return res.status(400).json({ message: 'Email and password are required' });
    }
    try {
        const user = await UserModel.findOne({ where: { email, password } });
        if (!user) {
            return res.status(401).json({ message: 'Invalid email or password' });
        }

        const token = jwt.sign({ userId: user.id }, JWT_SECRET, { expiresIn: '1h' });
        res.cookie('token', token, { httpOnly: true });
        res.json({ message: 'Login successful' });
    } catch (error) {
        res.status(500).json({ message: 'Error logging in', error: error.message });
    }
});
```

> Note HttpOnly :  
> Un cookie HTTPOnly n'est pas accessible via JavaScript dans le navigateur, ce qui améliore la sécurité en empêchant les attaques XSS (Cross-Site Scripting) d'accéder aux cookies sensibles comme les tokens d'authentification.  
> Le cookie n'est donc accessible que par le serveur lors des requêtes HTTP.  
> Voir la doc MDN : https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies#block_access_to_your_cookies

> Note : Dans une application réelle, il est important de hasher les mots de passe avant de les stocker dans la base de données. Utilisez des bibliothèques comme bcrypt pour cela.

> Note sur le rôle : Pour simplifier l'exemple, nous n'avons pas implémenté de gestion des rôles (admin, user, etc.). Dans une application réelle, vous devriez inclure le rôle en tant qu'attribut dans le token JWT et vérifier les autorisations dans les routes protégées.

## Middleware isLoggedInJWT
Le middleware isLoggedInJWT vérifie la présence et la validité du token JWT dans les cookies de la requête.

```js
function isLoggedInJWT(UserModel) {
    return async (req, res, next) => {
        const token = req.cookies.token;
        if (!token) {
            return res.status(401).json({ message: 'Unauthorized: No token provided' });
        }
        try {
            const decoded = jwt.verify(token, JWT_SECRET);
            req.userId = decoded.userId;
            // // req.user = await UserModel.findByPk(req.userId); // Récupérer l'utilisateur connecté
            // if (!req.user) {
            //     return res.status(401).json({ message: 'Unauthorized' });
            // }
            next();
        } catch (error) {
            return res.status(401).json({ message: 'Unauthorized: Invalid token' });
        }
    }
}
```

### Verrouiller les routes privées de notre application

Un middleware est une fonction qui s'exécute à l'appel d'une route, mais avant que la route demandée par l'utilisateur ne soit traitée par le router.

Concrètement, on peut exécuter la fonction isLoggedInJWT avant les routes qui nécessitent d'être connecté.

Les routes de mon serveur s'exécutent dans cet ordre :

```js
// Routes publiques
app.post("/register", (req, res) => {});
app.post("/login", (req, res) => {});

// Routes privées
app.get("/tasks", (req, res) => {});
app.get("/task/:id", (req, res) => {});
app.post("/task", (req, res) => {});
```

Un middleware peut être appelé avec la fonction app.use().

Il faut donc appeler app.use() avant les routes privées pour vérifier que l'utilisateur est bien connecté avant de tester l'accès à ces routes.

```js
// Routes publiques
app.post("/register", (req, res) => {});
app.post("/login", (req, res) => {});

app.use(isLoggedInJWT(User)); 

// Routes privées
app.get("/tasks", (req, res) => {});
app.get("/task/:id", (req, res) => {});
app.post("/task", (req, res) => {});
```

> Vous pouvez aussi verrouiller une route spécifique en fournissant le middleware en deuxième paramètre des méthodes `app.METHOD` :
> ```js
> app.get("/tasks", isLoggedInJWT(User), (req, res) => {
>    res.json(...)
> });
> ```

#### Obtenir l'utilisateur dans les routes privées

Pour l'instant, l'application permet à un utilisateur connecté de voir et d'ajouter des tâches. Le problème, c'est que toutes les tâches sont ajoutées au même utilisateur.

Il nous faut donc un moyen de récupérer facilement l'utilisateur connecté.

Il suffit de récupérer son id dans le token JWT et de s'en servir pour faire une requête dans la table User.

##### Créer une variable req.user

1. Modifier le middleware isLoggedInJWT pour créer une variable req.user contenant l'utilisateur connecté.

```js
function isLoggedInJWT(UserModel) {
    return async (req, res, next) => {
        const token = req.cookies.token;
        if (!token) {
            return res.status(401).json({ message: 'Unauthorized: No token provided' });
        }
        try {
            const decoded = jwt.verify(token, JWT_SECRET);
            req.userId = decoded.userId;

            // ++++++++++
            // Récupérer l'utilisateur connecté
            req.user = await UserModel.findByPk(req.userId); 
            if (!req.user) {
                return res.status(401).json({ message: 'Unauthorized' });
            }
            // ++++++++++

            next();
        } catch (error) {
            return res.status(401).json({ message: 'Unauthorized: Invalid token' });
        }
    }
}
```

Les middlewares ont un fonctionnement très pratique : ils peuvent modifier l'objet `req` avant de passer la main à la route suivante.

Ce qui signifie que dans TOUTES les routes privées, on peut maintenant accéder à l'utilisateur connecté via la variable req.user.
