# Sécuriser une API REST

Soit l'API REST suivante : elle n'est pas sécurisée et possède les routes :

- POST /register : pour enregistrer un utilisateur
- POST /login : pour connecter un utilisateur
- GET /profile : pour récupérer le profil de l'utilisateur connecté


*database.mjs*
```js
import { Sequelize, DataTypes } from "sequelize";

/**
 * Initialise la connexion à la base de données et définit les modèles User et Task.
 * @return {Promise<Sequelize>} L'instance Sequelize connectée à la base de données.
 */
export async function loadSequelize() {
    try {

        const login = {
            database: "app-database",
            username: "root",
            password: "root"
        };
        // ----  0. Connexion au serveur mysql ---- 
        // Connexion à la BDD
        const sequelize = new Sequelize(login.database, login.username, login.password, {
            host: '127.0.0.1',
            dialect: 'mysql'
        });


        // ----  1. Création de tables via les models ---- 
        // Création des models (tables) -------------//
        const User = sequelize.define("User", {
            username: DataTypes.STRING,
            email: DataTypes.STRING,
            password: DataTypes.STRING
        });



        // CRÉER LES TABLES AVANT LA FONCTION sync !
        // -----------------------------------------//
        await sequelize.sync({ force: true });
        console.log("Connexion à la BDD effectuée");

        return sequelize;
 } catch (error) {
        console.log(error);
    }
}
``` 

*main.mjs*
```js
import express from "express";
import cors from "cors";
import cookieParser from "cookie-parser";
import { loadSequelize } from "./database.mjs";

async function main(){
    try{
        const User = await loadSequelize().models.User;
        
        const app = express();
        app.use(cors());
    
        app.use(express.json());
    
        app.post("/register", async (request, response) => {
            try {
                const { username, email, password } = request.body;
                const user = await User.create({ username, email, password });
                response.json(user);
            }catch(error){
                response.status(500).json({ error: "Erreur lors de l'enregistrement de l'utilisateur" });
            }
        });
    
        app.post("/login", async (request, response) => {
            // Connecter un utilisateur
            const { email, password } = request.body;
            const user = await User.findOne({ where: { email } });
            if (!user || user.password !== password) {
                return response.status(401).json({ error: "Email ou mot de passe incorrect" });
            }
            response.json({ message: "Connexion réussie" });
        });
    
        app.get("/profile/:userid", async (request, response) => {
            // Récupérer le profil de l'utilisateur connecté
            const { userid } = request.params;
            const user = await User.findByPk(userid);
            if (!user) {
                return response.status(404).json({ error: "Utilisateur non trouvé" });
            }
            response.json(user);
        });
    }catch(error){
        console.error("Erreur lors du démarrage de l'application :", error);
    }
}
```


## Chiffrer le mot de passe des utilisateurs avec bcrypt

La route /register possède une faille de sécurité car elle ne chiffre pas les mots de passe des utilisateurs avant de les stocker dans la base de données.

```js
app.post("/register", async (request, response) => {
    try {
        const { username, email, password } = request.body;
        const user = await User.create({ username, email, password });
        response.json(user);
    }catch(error){
        response.status(500).json({ error: "Erreur lors de l'enregistrement de l'utilisateur" });
    }
});
```

Pour chiffrer les mots de passe des utilisateurs avant de les stocker dans la base de données, nous allons utiliser la bibliothèque `bcryptjs`. 

Lors de la création du modèle `User`, nous allons définir un setter pour le champ `password` qui va automatiquement chiffrer le mot de passe avant de l'insérer dans la table `User`.

*database.mjs*
```js
import bcrypt from "bcryptjs";
// ...
// ----  1. Création de tables via les models ---- 
// Création des models (tables) -------------//
const User = sequelize.define("User", {
    username: DataTypes.STRING,
    email: DataTypes.STRING,
    password: {
        type: DataTypes.STRING,
        // Hook pour chiffrer le mot de passe avant de le sauvegarder
        // +
        set(clearPassword) {
            const hashedPassword = bcrypt.hashSync(clearPassword, 10);
            this.setDataValue('password', hashedPassword);
        }
    }
});
``` 

La vérification du mot de passe lors de la connexion doit également être mise à jour pour comparer le mot de passe chiffré plutôt que d'effectuer une simple égalité.

```js
app.post("/login", async (request, response) => {
    // Connecter un utilisateur
    const { email, password } = request.body;
    const user = await User.findOne({ where: { email } });

    // +
    const isPasswordTheSame = bcrypt.compareSync(password, user.password)
    
    if (!user || !isPasswordTheSame) {
        return response.status(401).json({ error: "Email ou mot de passe incorrect" });
    }
    response.json({ message: "Connexion réussie" });
});
```

## Enregistrer le token JWT dans un cookie HttpOnly

Lors de la connexion d'un utilisateur, nous allons générer un token JWT et l'envoyer au client dans un cookie HttpOnly.

Un cookie marqué comme HttpOnly n'est pas accessible via JavaScript côté client.

Cela empêchera le JavaScript côté client d'accéder au token, ce qui améliore la sécurité en limitant les risques liés aux attaques de type Cross-Site Scripting (XSS).

Il faut :
1. Importer la bibliothèque `jsonwebtoken`
2. Définir une clé secrète pour le JWT.
3. Ajouter la bibliothèque `cookie-parser` pour gérer les cookies
4. Générer un token JWT lors de la connexion
5. Envoyer le token dans un cookie HttpOnly

```js
// 1. Importer la bibliothèque jsonwebtoken
import jwt from "jsonwebtoken";
import cookieParser from "cookie-parser";

// 2. Définir une clé secrète pour le JWT
const JWT_SECRET = "cle_secrete_kwt";

// 3. Ajouter la bibliothèque cookie-parser pour gérer les cookies
app.use(cookieParser());

app.post("/login", async (request, response) => {
    // Connecter un utilisateur
    const { email, password } = request.body;
    const user = await User.findOne({ where: { email } });

    const isPasswordTheSame = bcrypt.compareSync(password, user.password)
    
    if (!user || !isPasswordTheSame) {
        return response.status(401).json({ error: "Email ou mot de passe incorrect" });
    }

    // 4. Générer un token JWT lors de la connexion
    const token = jwt.sign(
        { userid: user.id },
        JWT_SECRET,
        { expiresIn: '1h' }
    );

    // 5. Envoyer le token dans un cookie HttpOnly
    response.cookie("token", token, { httpOnly: true });

    response.json({ message: "Connexion réussie" });
});
```

> La réponse HTTP brute ressemblera à ceci :
> ```http
> 200 OK HTTP/2
> Set-Cookie: token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VyaWQiOjEsImlhdCI6MTY4ODUwMjI0NSwiZXhwIjoxNjg4NTA1ODQ1fQ.--abc123def456ghi789jkl012mno345pqr678stu901vwxyz; HttpOnly;
> Content-Type: application/json; charset=utf-8
>
> {"message":"Connexion réussie"}
> ```
> Notez comment la méthode response.cookie ajoute un en-tête Set-Cookie à la réponse HTTP.


## Verrouiller les routes avec un token JWT

La route /profile est accessible sans authentification, ce qui n'est pas sécurisé.

Il est nécessaire d'utiliser le userId présent dans le token JWT plutôt que de le passer en paramètre dans l'URL.

1. Créer une fonction middleware checkJWTLogin qui va vérifier la présence et la validité du token JWT dans les cookies de la requête.
2. Utiliser le middleware checkJWTLogin pour protéger la route /profile.

```js
// ...
const JWT_SECRET = "cle_secrete_kwt";
// ...
// + checkJWTLogin middleware passé en 2nd paramètre
app.get("/profile/:userid", checkJWTLogin, async (request, response) => {
    // Récupérer le profil de l'utilisateur connecté
    const { userid } = request.params;
    const user = await User.findByPk(userid);
    if (!user) {
        return response.status(404).json({ error: "Utilisateur non trouvé" });
    }
    response.json(user);
});

// Déclaration de la fonction middleware qui vérifie la validité du token JWT
function checkJWTLogin(request, response, next) {
    const token = request.cookies.token;
    if (!token) {
        return response.status(401).json({ error: "unAuthorized" });
    }
    try {
        // 
        const decoded = jwt.verify(token, JWT_SECRET);
        request.userid = decoded.userid;
        next();
    } catch (error) {
        return response.status(401).json({ error: "unAuthorized" });
    }
}
```

## Définir la clé secrète pour le JWT dans les variables d'environnement

La clé secrète ne doit pas être visible en clair dans notre code source car :
- Elle peut être volée si quelqu'un a accès à notre code source.
- Si nous utilisons un système de contrôle de version (comme Git), la clé secrète pourrait être exposée publiquement si le dépôt est public.

Il faut donc définir la clé secrète à l'exécution du programme dans ce que l'on appelle une variable d'environnement. C'est-à-dire une variable définie dans le système d'exploitation et accessible par notre application en cours d'exécution.

1. Utiliser l'attribut process.env pour accéder à la variable d'environnement.

```js
const JWT_SECRET = process.env.JWT_SECRET;
```

2. Définir la variable d'environnement JWT_SECRET avant de lancer notre application.

```bash
export JWT_SECRET="clé_secrete"
node main.mjs
```

Il vous faudra exécuter cette commande dans le terminal avant de lancer votre application Node.js.

En production, il faudra définir cette variable d'environnement sur le serveur où l'application sera hébergée.

Créez également un fichier `.env` à la racine de votre projet pour définir vos variables d'environnement en développement.

*.env*
```
JWT_SECRET="clé_secrete"
```

N'oubliez pas d'ajouter `.env` à `.gitignore`.

Et utilisez la commande source pour charger les variables d'environnement avant de lancer votre application.

```bash
source .env
```
